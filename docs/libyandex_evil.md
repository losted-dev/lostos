# libyandex_evil.so — что внутри и что из этого можно взять

Файл: `/system/vendor/quasar/libs/libyandex_evil.so` (ARM 32-bit, 4.9 МБ, stripped, TFLite). Копия для изучения: `ref/evil/`.
Это стоковая библиотека обработки голоса Яндекса. Смотрел только экспортируемые символы и строки (статический разбор), ничего не запускал.

## Что lostOS уже использует
- `YandexVqeC_*` ядро: Create/Process/GetOutputChannelData, пресеты (`bergamot`) — эхоподавление, шумоподавление, AGC, лучеформирование.
- `spotter_*`: слово «Алиса» (`spotter_create_multichannel`, `get_next_event`, `submit_raw_data`).

## Что в библиотеке есть, а мы не используем
| Возможность | Символы | Что даёт lostOS | Сложность |
|---|---|---|---|
| **Ультразвуковой датчик присутствия** | `UltrasoundSonar_*`, `UltrasoundDetector_*` | колонка излучает ультразвук и по эху видит человека в комнате: «я дома», свет по приходу, автовыключение музыки в пустой комнате | средняя: нужна сигнатура функций (Ghidra) и ультразвуковой тон в выходной поток |
| **Умный эквалайзер** | `SmartEqualizer_*` (`frequency_domain_smart_equalizer.cpp`) | авто-подстройка звука под громкость и микрофон | средняя |
| **Коррекция под комнату** | `RoomCorrection_*` (`AnalyzeSpeaker/Mic`, `ProcessPlaybackAudioChunk`) | «настроить звук под комнату» кнопкой в панели | высокая (нужны тестовые сигналы) |
| **Контр-активация** | `spotter_multi_conf_get_local_counteractivation_*` | колонка не просыпается на слово «Алиса» из телевизора и из собственного голоса | низкая-средняя: уже лежит в моделях `vqe_models/` |
| Детектор «на улице» | `GetOutdoorsDetectorResult`, `outdoors_classifier` | не нужен | — |
| Свои слова пробуждения | `spotter_submit_phoneme/word`, `spotter_get_phrase`, каталог `/system/vendor/quasar/vqe_models/` | выбор слова, не только «Алиса» | зависит от моделей |
| Телеметрия DSP | `DspClient_PullSingleTelemetryEvent`, `GetDegradationModeSwitchHistory` | диагностика качества звука в панели | низкая |

## Рекомендация
1. **Присутствие по ультразвуку** — самая ценная и ни у кого не встречающаяся функция. Начать с проверки: поднимается ли излучение на динамике Мини 3 (ультразвук ~19–20 кГц, нужен тихий тон поверх музыки) и отдаёт ли `UltrasoundDetector_Process` осмысленный результат. Датчик вынести как плагин «Присутствие» (см. `lostos-architecture.md`).
2. **Контр-активация** — ставится почти бесплатно и уменьшает ложные срабатывания.
3. Остальное — после плагинной системы.

Ограничение: символы без прототипов, нужен разбор в Ghidra (аргументы, структуры конфигов). Это отдельная задача, делается только на вашей колонке.

## Результат разбора в Ghidra (2026-10-25)
Ghidra 12.2 разобрала библиотеку целиком (скрипт `ref/evil/ghidra_scripts/DecompileExports.java`, результат `ref/evil/ultrasound_decomp_part.c`). Форма C-API ультразвука:

```c
int UltrasoundSonar_Create(Sonar **out, const Config *cfg);        // cfg: первое поле передаётся в UltrasoundSonarAnalyzer
int UltrasoundSonar_AddChannelData(Sonar *s, bool flag, a, b, c);  // flag + три аргумента (указатель на PCM, число кадров, ...)
int UltrasoundSonar_Process(Sonar *s, int *result);                // результат классификатора (число)
int UltrasoundSonar_Reset(Sonar *s);
int UltrasoundDetector_Create(Detector **out, const Config *cfg);  // «слушатель» без излучения; AddChannelData/Process через виртуальные методы
```
Классификатор внутри: корреляторы (`runCorrelators`) по известной излучаемой последовательности, то есть сонар **сам ничего не играет**: хост должен проиграть ультразвуковой сигнал в динамик и подать в `AddChannelData` и эталон, и запись микрофона.

Важное:
- В стоковой конфигурации (`quasar.cfg`, `launch.json`, `vqe_models/`) ультразвук **нигде не включён**, то есть Яндекс его на этих колонках не использует: структура конфига и сам излучаемый сигнал нигде не лежат готовыми.
- Нужно подобрать формат конфига (поля неизвестны) и сигнал, а ещё проверить, что динамик и микрофоны Мини 3 вообще передают 18–20 кГц (дискретизация 48 кГц это позволяет, но железо не проверено).
- Практичный путь без чужих структур: **свой датчик**. Излучать тихий тон около 19 кГц и по спектру в микрофоне (изменение амплитуды и допплер) определять присутствие; в прошивке уже есть анализатор спектра (`audio/spectrum.cpp`). Минус: слышат животные и часть людей, постоянный тон на динамике. Оставляю как опцию, нужен ваш выбор.

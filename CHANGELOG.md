# Changelog

lostOS — прошивка-оболочка для Яндекс Станций, форк [pulsar](https://github.com/Morvex885/pulsar) (MIT, см. LICENSE).

## [Unreleased] — 2026-10-29
### Добавлено
- Значок AirPlay на больших колонках: в профиле появился ключ `airplay_model`. Станция, Станция 2 и Станция Миди объявляют `AudioAccessory6,1` (большой HomePod), и iPhone и Mac рисуют в списке значок HomePod, а не HomePod mini; маленькие колонки остаются как были. Имя заменяется в копии программы приёмника на месте (длина та же), оригинал не трогается. Проверено: разбор и проверка ключа (тест профилей), замена имени на настоящей программе (3 места, длина та же), сборка прошивки; значок на iPhone и работу AirPlay с заменённым именем на большой колонке не проверял
- Установщик ищет чужие моды на станции до копирования файлов (одним запросом, только чтение): Spotify Connect мода (spotiya), ночник на светодиодной панели, arecord, который держит АЦП, панели эффектов, Luna, чужие AirPlay и плееры, AliceBridge (его только упоминает). Для каждого он говорит, чем тот мешает, и показывает строки, которые запускают его при загрузке (их не трогает). `--stop-mods` останавливает работающие мешающие моды до перезагрузки; без него установщик спрашивает подтверждение (`--yes` и мастер: печатают и идут дальше). Те же моды видит `--doctor`. Проверено тестами на разборе реального списка процессов и чтением Мини 3 (чужих модов там нет); на Станции 2 не проверено
- Плагины на JavaScript, работающие на самой колонке: среда `lostos-js` (QuickJS-ng, статическая ARM-программа ~670 КБ) в песочнице нативных плагинов. API: команды для ассистента, HTTP(S) через прошивку, проигрывание потоков, хранилище, события, подсветка, таймеры (`docs/plugins-js.md`). Пакет с `"device": {"runtime": "js"}` ставится той же командой `install … js`, подпись колонка проверяет сама. Плагин занимает меньше 1 МБ памяти (радио: 840 КБ). Установщик кладёт среду в `/data/lostos/lostos-js`, релиз собирает её (`lostos-js-armhf.bin`, `runtime/` в `lostos-payload.zip`).
- Новые методы протокола плагинов: `http`, `play`/`stop`, `tool`/`toolresult`; команда `plugin call` с сервера; команды и ответы плагинов в датчике `plugins_state`.
- HTTP-клиент прошивки: любой метод, тело запроса, обычный `http://` (для сервисов домашней сети); `https_get` для обновлений остался только HTTPS.
- Сборка демона под Android (Станция 1): `make ARCH=android`, alsa-lib статически, `android_compat` для вызовов, которых нет в API 23.
- Слова активации: lostOS предлагает те, для которых на колонке есть заводская модель (`spotter_models/activation`). Кроме «Алиса» и «Яндекс» это «Yasmina» там, где её модель есть (например, Мини 3). Активно одно слово, выбор в Home Assistant.
- Станция 1: захват через tinyalsa с распаковкой S32 в 2×16 бит, опорный сигнал с Loopback (второе устройство с понижением частоты), вывод `openslessink`, громкость регуляторами усилителя по таблице стокового HAL (`mixer=hardvol`, `hardvol=tinyalsa:1,/system/etc/hardvol_ti.xml`), кнопки и колесо на GPIO, подсветка через SN3236 по I2C (`models/tulip-d1.conf`).

- Станция 1: автозапуск (`deploy/boot-android.sh`, одна строка в `/system/etc/rc.local`), связь с сервером lostOS.
- `ctl.sh press`: нажатие кнопки Алисы с самой колонки (SIGUSR1 демону), например чтобы подтвердить привязку станции, когда рядом никого нет.

### Исправлено
- Установщик выбирает модель по всему списку `compatible`, а не по первому имени: у колонки там сначала точное имя платы, потом семейство (Мини 3 в виде инженерного образца это `yandex,bergamot-evt1 yandex,bergamot`). Берётся первое имя, которое знает каталог моделей; если известна только часть до последнего дефиса (`bergamot-evt2`), берётся она; новое имя остаётся как есть. Раньше, после того как разбор имён научился дефису (для `station-midi`), такая Мини 3 определялась как «неизвестная колонка»
- «Вперёд» и «назад» (кнопки колонки, панель, Home Assistant), пока играет поток плагина, уходят этому плагину событием `transport` (`lostos.on("transport", fn)`, без отдельного разрешения): радио переключает станции.
- Поток плагина (радио) виден в «Сейчас играет»: `lostos.play(url, {title, cover, source})` попадает в состояние медиа как источник `plugin` с id плагина, его подписью источника, названием и картинкой; пауза и «играть» действуют на него, а не на приостановленный Spotify. Среда JS передаёт `cover` и `source`. Ответ плагина на вызов с сервера может быть до 12 КБ (страница плагина в панели).
- Обновления колонки больше не требуют файла `/data/lostos/allow-update`: колонка проверяет релизы сама, выключить можно файлом `/data/lostos/no-update`. Автоустановка по-прежнему выключена, пока её не включат (теперь и в панели).
- Android (Станция 1) берёт из релиза свою сборку `lostos-android.bin`, а не Linux-сборку `lostos-aarch64.bin`; релиз собирает её (NDK r27c). В `system_stats` есть `arch`, по нему панель показывает размер файла.
- SSH (`ssh/start.sh`) слушает только IPv4: за домашним роутером это локальная сеть, а публичный IPv6-адрес колонки был бы виден из интернета.
- Установщик не идёт за перенаправлением сервера на другой адрес или с HTTPS на HTTP (из PR sorried, losted-dev/lostos#1).
- Связь с сервером и проверка подписей не работали там, где в OpenSSL прошивки нет Ed25519 (Станция 1: OpenSSL 1.1.0e): теперь запасной путь на Monocypher (RFC 8032, закреплённая версия в `third_party/fetch.sh`).
- HTTPS на Android: сертификаты берутся из `/system/vendor/quasar/ca-certificates.crt`, если нет `/etc/ssl/certs/ca-certificates.crt`.
- Песочница плагинов убивала любую программу на musl 1.2 при первом `clock_gettime`: разрешены 64-битные двойники уже разрешённых вызовов времени (`clock_gettime64` и др.).
- Длинный ответ плагину (тело HTTP) обрезался, если не помещался в буфер сокета: теперь дописывается.
- Интернет-радио по протоколу ICY не играло («No decoder available for type application/x-icy»): плеер больше не просит ICY-метаданные, станция отдаёт обычный поток.

## Ранее — 2026-10-25
### Изменено
- Проект переименован в lostOS: бинарник `lostos`, каталог на колонке `/data/lostos` (`/data/pulsar` остаётся ссылкой для совместимости), лог `/tmp/lostos.log`.

### Добавлено
- Громкость Spotify Connect и Bluetooth (AVRCP) связана с главной громкостью колонки в обе стороны.
- Громкость, изменённая из панели или Home Assistant, показывается на кольце и экране колонки.
- Переключатель «Звук громкости» (стоковый звук Станции на каждый шаг).
- Обложка из потока AirPlay (PICT) отдаётся через DLNA-плеер и панель.
- Кнопки «следующий» и «предыдущий» в AirPlay больше не зеркальны.
